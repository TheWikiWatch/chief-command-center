home passed, released on the early channel; promote after a day or two of use. The e2e run also found that Send again

## 1. The upgrade itself

Done:

- **Patch queue.** 0003 drops its cron hunk (Bot Chat delivery now runs in-process upstream); 0005 goes (upstream pins
  edge-tts 7.3.1 itself, same hashes); 0006 is re-anchored on a changed line. New **0007**: in 0.22.5 an agent cron
  job for a profile the running gateway doesn't own starts the install root's own gateway to run it
  (`cron/scheduler_authority.run_canonical_job` → `connect_gateway` → `ensure_gateway_runtime`). The app runs only
  the chief's gateway (`gateway.standalone: true`), so every bot routine would start a second, detached gateway on
  the root profile. The compatibility run showed exactly that (`--profile default gateway run --idle-exit`, ticking
  `default` and the bot). On the owner's install the root profile is the adopted original Hermes home. 0007 lets a
  standalone gateway run those jobs itself, as 0.22.0 did; a multiplexer and the CLI keep upstream's path.
- **Fleet.** `launch_model_seed` moved to `hermes_cli.profile_model_seed`; minting also uses its new
  `merge_endpoint_seed`.
- **Quick connections.** `managed_client` now requires `creates_guest=`: every Connect failed with a TypeError
  (the names-only check can't see it; the test fake now requires the keyword too). A connect that fails also closes
  its operation, as Hermes's own runner does.
- **Nous sign-in.** Every sign-in now *replaces* the signed-in account instead of refusing. Service rows no longer
  offer "Sign in to Nous" to a signed-in owner, and the bridge refuses a second sign-in. An unused code reads as
  expired again (it's now an error with reason `timeout`). The session table is read from the module that owns it.
- **Routines.** A run Hermes refused before it started is relayed as a failure; Hermes's own "couldn't confirm this
  run" pauses are said in plain words.
- **Contracts.** The routines contract still expected the bot's name in the message text, so the Hermes
  compatibility workflow on GitHub has been red since 0.1.47; fixed. Chat controls now checks that no gateway starts
  on the root profile.

To do (no choices here; these keep the app working as it did):

1. **The chat around a restart.** Hermes 0.22.5 queues every message durably per conversation.
   - A reply cut off by a planned stop (quitting, an update) is now stored as a `failed_turn` row ("Gateway
     restarting: this turn was interrupted…"). Our transcript doesn't read `display_kind`, so it shows, and is
     spoken, as a reply from the chief. It becomes the app's failed-turn marker with "Send again"; `hidden` rows are
     skipped.
   - A reply lost to a crash or a forced quit **pauses the conversation**: the next message is saved but not
     answered, and Hermes posts "⏸️ … Send /discard to drop the lost turn … or /reset". That becomes a card: what
     happened, **Continue** (sends `/discard`) and **Start fresh** (`/reset`).
   - Notices the app already shows in its own way leave the chat and the phone: busy acknowledgements ("⏩ Steered
     into current run…", "⏳ Queued…", "⚡ Interrupting…") and "your message is saved and will be answered when…".
     Provisioning turns the steer echo off for our platform only and marks Hermes's one-time "/busy" tip as seen
     (it tells the owner to type a command that would break steering).
   - A message added while the chief works shows as typed (Hermes stores it wrapped in an out-of-band frame).
2. **History clean-up.** Upstream switched `sessions.auto_prune` off by default and asks weekly in the chat, with
   slash commands, when the disk is low. Provisioning keeps 0.22.0's behaviour (on) unless the owner set it.
3. **Nous plans.** Nous model rows now carry `plan_usage`; `usage` disappears once a window is full and `limit` is
   gone, so the model picker's "17% left" chip went silent exactly when a limit is reached. Read `plan_usage`.
4. **Sign-in result.** Hermes now moves a free guest's apps to the account by itself and can move the chief off the
   free model. The sign-in says who signed in, what moved, what to connect again, and the new model.
5. **Local models.** A download now has a draft-model phase that restarts the progress numbers; it shows as its own
   step. The engine moves from b11370 to b11671, so "Update engine" appears; that update also downloads each
   downloaded model's draft (about 1 GB) and restarts the server. Say so in the release notes.
6. **Ship.** Rebuild the payload with 0007, run the compatibility suite, then the e2e home on 7795 (a copy of its
   0.22.0 state, so the upgrade path is what testers get), and the Electron smoke test. One early release, then a
   promote after use.

## 3. Not now

- **One host gateway per install.** Upstream calls `gateway.standalone` (how the app runs the chief) a temporary
  shim and plans one host gateway per install (`hermes gateway migrate --multiplex`). Patch 0007 is the bridge to
  that. When upstream removes standalone, the app has to run the root's multiplexer itself, with the chief and the
  bots as served profiles. That's a project of its own.
- Not reachable from a chat platform like ours: MCP progress (local viewers only), editing a queued prompt and the
  "working folder is gone" message (local sessions only).
- New voice, image and search providers are catalog plugins (kokoro-tts is Apple-only; web-local, web-deepseek,
  meshy); plugin-declared OAuth is CLI-only.
